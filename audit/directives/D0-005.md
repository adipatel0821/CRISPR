Affected files: backend/schemas/contracts.py (ErrorDetail.code: str); backend/api/main.py (CP0 health); in-progress .claude/worktrees/wf_81b5f792-674-4/backend/api/errors.py (UNVERIFIED)
Finding:
contracts v1.1 §4 fixes a closed set of error codes and HTTP statuses: VALIDATION_ERROR 400, UNAUTHORIZED 401, NOT_FOUND 404, CONFLICTING_FACTS 409, UNSUPPORTED_PRODUCT 422, INSUFFICIENT_INFORMATION 422, EXTRACTION_FAILED 422, DATA_MODE_RESTRICTED 403, NOT_IMPLEMENTED 501, LLM_UNAVAILABLE 503 (+fallback_available), LLM_MALFORMED_OUTPUT 502, RATE_LIMITED 429, INTERNAL 500. contracts.py models `code` as a free string with no enum. The generated TS types therefore carry `code: string`, and the frontend cannot switch on codes exhaustively. Drift is already visible: Agent 4's in-progress errors.py (UNVERIFIED) emits METHOD_NOT_ALLOWED and HTTP_ERROR, which are not in the contract. In the committed CP0 app, unknown routes return FastAPI's default `{"detail": "Not Found"}` envelope instead of ErrorBody. GET /api/v1/health returns an unstructured 500 when LLM_DATA_MODE holds an invalid value such as "PAID". A startup misconfiguration should fail fast or degrade, not 500 on the health probe.
Evidence:
audit/evidence/health_check_CP0.txt: "bad mode -> 500 Internal Server Error"; "404 shape -> 404 {"detail":"Not Found"}". contracts/schemas.json ErrorDetail.code = {"type": "string"}. Grep of wt4 api/errors.py: `405: "METHOD_NOT_ALLOWED"`, default `"HTTP_ERROR"`.
Required correction:
Add an `ErrorCode` StrEnum with the 13 contract codes to contracts.py, plus an `ERROR_HTTP_STATUS` map. Type `ErrorDetail.code: ErrorCode` and regenerate the schemas and TS types. Map 405 and any other unlisted status to an existing code (for example VALIDATION_ERROR for 405 or 413, INTERNAL otherwise), or add codes through an ADR. Validate LLM_DATA_MODE at startup: either fall back to "off" or "synthetic_only" with a logged warning, or refuse to start. Health must not 500.
Done when:
Every error response body validates against ErrorBody with a code from ErrorCode. Unknown routes return {"error":{"code":"NOT_FOUND",...}}. Health returns 200, or a degraded status, when LLM_DATA_MODE is invalid.
Verification test:
TestClient: GET /api/v1/nope → 404 with error.code == "NOT_FOUND". DELETE on a GET-only route → code ∈ ErrorCode. With env LLM_DATA_MODE=PAID, GET /api/v1/health status_code != 500. A parametrised test asserts that every code emitted by api/errors.py is a member of ErrorCode.
Status: OPEN
END DIRECTIVE
