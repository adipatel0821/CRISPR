CORRECTION DIRECTIVE:
Directive ID: D0-004
Issued by: Agent 5 (Independent Auditor)
Phase: CP0 (Foundation)
Assigned to: Supervisor (CP0 author of contracts.py); Agent 4 owns backend/schemas going forward
Severity: HIGH
Affected files: backend/schemas/contracts.py (FinancialFact, FactInput, Uncertainty, VerifiedFinancialTerm, ManualOfferRequest, QuestionResponse, Metric/ScheduleRow money fields); contracts/schemas.json and web/src/lib/contracts.ts (regenerate afterwards)
Finding:
contracts.py implements none of the contracts v1.1 §5 "Validation rules (Pydantic v2)":
- currency must be a 2-dp decimal string ≥ 0 (except where the contract allows negatives)
- rates must satisfy 0 ≤ r < 1
- term_months must be an integer from 6 to 96
- uncertainty "range" requires user-given low and high
- free text must be ≤ 1,000 chars with control characters stripped
All money, rate and term fields are bare `str`. Floats are correctly rejected, but any string is accepted, including non-numeric, negative, 3-dp and out-of-range values. Acceptance test A-17 (CP1: "negative income, term 500 → 400/422 with actionable message; no crash") depends on these validators. Three agents are already parsing values independently in their worktrees (UNVERIFIED), and the semantics have started to drift. For example, Agent 1's engine/money.py to_decimal silently strips "$" and ",", and Agent 1 classifies rate ≥ 1 as an unsupported product, which would surface as 422 UNSUPPORTED_PRODUCT instead of 400 VALIDATION_ERROR.
Evidence:
audit/evidence/probe_cp0_output.txt:
  FinancialFact value 'abc' (value_type currency) -> accepted
  FinancialFact value '-5.123' (currency)          -> accepted
  VerifiedFinancialTerm term_months '500'          -> accepted
  VerifiedFinancialTerm apr '1.5'                  -> accepted
  Uncertainty(kind='range') with no low/high       -> accepted
  ManualOfferRequest terms {'principal': 20000.0} (float) -> silently coerced to int 20000
Required correction:
Add reusable annotated types and validators in contracts.py, for example `Money = Annotated[str, AfterValidator(...)]`, `Rate`, `TermMonths` and `FreeText`. Apply them to the input models: FactInput (by value_type or ontology key), ManualOfferRequest.terms (by TERM_VALUE_TYPES), QuestionResponse typed values and Uncertainty. Apply them to output models where the shape is fixed: ScheduleRow, and Metric.value as an optionally signed decimal string. Use strict types so floats and ints are never coerced into money. Allow negative money only where the contract does (F08/F09 deficits, trade_in_equity). Then regenerate contracts/schemas.json and the TS types, and record the change in DECISIONS.md because a schema change after CP0 affects all agents.
Done when:
Invalid currency, rate and term values raise ValidationError, and the API maps it to 400 VALIDATION_ERROR with a field message. Valid reference-case values still validate. schemas.json is regenerated and committed, and the existing tests pass.
