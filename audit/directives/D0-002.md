Finding:
`debt_requirements` parses a known `debts.count` with `int(_decimal(value) or 0)`. Any value that does not parse as a number ("two", "none") becomes 0, which means "no debts". Fractions are truncated toward zero ("0.4" → 0, "1.5" → 1). Negative values are treated as no debts ("-1"). NaN and Infinity raise uncaught ValueError and OverflowError. When an invalid count is read as 0, cashflow_impact, reserve_impact, stress_test and alternatives are reported as available while the user's debt payments are unknown. That breaks contracts §1.1 ("unknowns are never zero") and acceptance test A-22 ("no sum uses a missing value"), and lets the engine compute monthly_left_* with no debts. The readiness evaluator is the single source for intake and engine (IMP-002), so nothing downstream catches this. contracts.py has no validators either (see D0-004).
Evidence:
audit/evidence/probe_cp0_output.txt (black-box run of evaluate_readiness("cashflow_impact", ...)):
  debts.count='two'      -> available True, missing []
  debts.count='none'     -> available True
  debts.count='0.4'      -> available True
  debts.count='-1'       -> available True
  debts.count='NaN'      -> EXCEPTION ValueError: cannot convert NaN to integer
  debts.count='Infinity' -> EXCEPTION OverflowError
  debts.count='1e3'      -> 1000 required debt-item keys generated
Required correction:
Treat `debts.count` as known only when it is a finite, non-negative integer within a sane bound (for example ≤ 20, configurable). Treat anything else as unknown: return it in `missing`, or reject it at intake with VALIDATION_ERROR through the D0-004 validators. Never treat it as 0 and never raise. Apply the same rule in engine/inputs.py build_inputs, ideally through one shared helper.
Done when:
evaluate_readiness never raises for any string debts.count. Non-integer, negative, non-finite and out-of-bound counts make every debt-dependent analysis unavailable with "debts.count" in missing. Valid "0" and "2" behave as they do today. The existing 4 CP0 tests still pass.
Verification test:
Parametrised pytest over ["two","none","0.4","1.5","-1","NaN","Infinity","1e3",""] asserting available is False, "debts.count" in missing, and no exception. Hypothesis property: for any text value, evaluate_readiness returns an AnalysisReadiness. Agent 5 re-runs audit/evidence/probe_cp0.py.
